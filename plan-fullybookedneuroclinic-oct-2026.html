01  WHAT WE FOUND

The restriction comes from what the sites send to Meta

Meta puts each domain into a category. Once a clinic site is labelled Health and Wellness, every pixel event from that domain is filtered the same way, and the media buyer loses the signal the campaigns optimize on. Below is what usually triggers it on neurofeedback sites. I will confirm each item site by site in week one.

High impact

Condition names are leaving the site with every event

Meta reads page URLs, page titles, button text, event names and custom parameters. Pages such as an anxiety or ADHD treatment page put a health condition into every PageView and Lead. That is the pattern that gets a domain classified and its data blocked.

SignalTypical clinic setupClean setup
Page URL sentFull path with the condition namePath and query string trimmed in core setup
Event namesCustom names that describe the conditionNeutral standard or custom names
Custom parametersSymptom, service or form answersNone, or value and currency only
Thank you pageURL names the treatment bookedOne neutral confirmation URL
Form dataPassed in the URL query stringKept server side, never in the URL
High impact

Lower funnel events are restricted first

Under the health category, the website events closest to a booking are the ones Meta limits for optimization. Campaigns need a replacement signal that Meta still accepts, otherwise they optimize toward clicks.

EventTypical status once restrictedReplacement path
Website LeadLimited for optimizationInstant Form leads optimized on platform
Booking or ScheduleLimited for optimizationCRM booking events through the Conversions API, where policy allows
Custom events with health termsBlockedRemoved or renamed
PageView and ViewContentUsually still receivedKept for reporting and audiences

Statuses differ by dataset. The audit records the real status for each domain in Events Manager.

Medium impact

Measuring bookings and optimizing ads are two separate jobs

Even when Meta cannot optimize on a booking, your team still needs to count bookings per clinic and per campaign. Right now both depend on the pixel. They should not.

TodayClinic website→Pixel→Meta blocks data→No bookings counted
After the planBooking form→GoHighLevel CRM→GA4 and dashboard→Every booking counted
02  THE 30 DAY PLAN

Five steps, in this order

No workarounds that could get a Business Manager or ad account restricted. Every change stays inside Meta's rules.

Week 1Week 2Week 3Week 4
1. Domain and event audit
2. Clean outgoing data
3. New conversion signal
4. Booking measurement
5. Clinic rollout SOP
1

Audit every dataset, domain and event

  • Map each clinic site to its pixel, dataset, domain status and restriction notice
  • List every event and parameter each site sends, and flag the ones carrying health terms

Why: you need to know which site is restricted and what caused it before changing anything.

2

Clean the data that leaves each site

  • Set core setup to trim URLs and block unneeded parameters
  • Rename custom events, move to neutral thank you pages, keep form data out of URLs
  • Request a category review for any site that is miscategorized

Why: removes the trigger and stops new restrictions on standard events.

3

Give the campaigns a signal Meta still accepts

  • Test Instant Form lead campaigns with qualifying questions next to website campaigns
  • Connect GoHighLevel to the Conversions API so booked and attended assessments flow back where policy allows

Why: ad sets optimize toward real patients again instead of clicks.

4

Count every booking outside Meta

  • GA4 with server side GTM, consistent UTMs per clinic and campaign
  • One Looker Studio dashboard: leads, booked assessments and cost per booking per clinic

Why: your team reports results to clinics even when Meta's data is limited.

5

Turn it into an onboarding standard

  • A written setup checklist for every new clinic site and ad account

Why: with 20+ practices, each new clinic should launch clean from day one.
